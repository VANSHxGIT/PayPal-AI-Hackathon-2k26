# UI/UX Design Specification

## 1. Design Philosophy
The merchant dashboard should look like a professional, enterprise-grade financial tool. It must convey trust, speed, and automation. Use a clean, dark-mode preferred theme (slate grays, PayPal blues, and success greens).

## 2. Core View: The Dispute Command Center (AG Grid)
The primary interface is a single-page application featuring an advanced AG Grid data table.

**Grid Columns:**
*   `Dispute ID`: Alphanumeric identifier (Clickable to open details).
*   `Transaction ID`: Original PayPal transaction reference.
*   `Amount`: Formatted in USD.
*   `Reason Code`: E.g., `ITEM_NOT_RECEIVED`, `UNAUTHORIZED`.
*   `AI Action`: Status badge (e.g., 🟢 `Auto-Defended`, 🟡 `Processing`, 🔴 `Manual Intervention Required`).
*   `Date Initiated`: Timestamp.

## 3. Detail View: The Evidence Modal
When a user clicks a row, a modal appears showing the AI's work:
*   **Left Pane (Raw Data):** The raw logs fetched from Elastic (Shipping tracking, customer emails).
*   **Right Pane (AI Defense):** The synthesized response generated by the LLM that was submitted to PayPal.
*   **Action Footer:** Buttons to "View in PayPal Sandbox" or "Download PDF Summary".

## 4. Visual Cues for the Demo Video
To make the 3-minute video impactful, include a "Live Feed" or "System Logs" terminal window on the UI that visibly scrolls when the webhook is received and the AI is thinking. This makes the invisible backend processes visible to the judges.
